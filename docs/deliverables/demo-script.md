# CampusRun 演示录屏脚本

> 目标：3–5 分钟录完「注册 → 发单 → 抢单 → 履约 → 确认」完整闭环。
> 对着这份脚本念即可，不需要背。

---

## 〇、录屏前的准备（开录之前做完，不要录进视频）

### 1. 起服务（三个终端，按顺序）

```bash
# 终端 1：依赖
docker start cr-pg cr-redis-alt2

# 终端 2：后端
cd D:\王思嘉\campus-run\backend
set DATABASE_URL=postgresql+psycopg://campusrun:campusrun@127.0.0.1:5433/campusrun
set REDIS_URL=redis://127.0.0.1:6600/0
C:\Users\shen\.workbuddy\binaries\python\envs\campusrun\Scripts\python.exe -m uvicorn app.main:app --port 8000

# 终端 3：前端（真接口模式）
cd D:\王思嘉\campus-run\web
npm.cmd run build
npm.cmd run preview
```

浏览器打开 <http://127.0.0.1:4173>

> **为什么用 preview 而不是 dev**：preview 跑的是生产构建、连真后端。老师若问「这是真跑还是假数据」，你有底气。
> 若 preview 出问题，退回 `npm.cmd run dev`（mock 模式），但**口播里要如实说「这是演示数据」**。

### 2. 清空演示数据（重要，否则大厅一堆旧单）

```bash
docker exec cr-pg psql -U campusrun -d campusrun -c "TRUNCATE order_progress, orders RESTART IDENTITY CASCADE;"
```

### 3. 准备两个浏览器窗口

- 窗口 A（左）：Chrome 普通窗口
- 窗口 B（右）：Chrome **无痕窗口**（无痕才不会有同一个 localStorage 登录态）

两个窗口并排，录屏时能同屏看到双角色。

### 4. 预演一遍

**必须先完整走一遍再正式录**。常见卡点：
- POI 下拉是空的 → 没跑种子：`python scripts/seed_pois.py`
- 发单报「不在可发单时间」→ 当前不在 07:00–23:00，**录屏请安排在这个时间段内**
- 抢单报 403 → 抢的是自己的单，确认窗口 B 登录的是另一个号

## 一、分镜脚本

### 【0:00–0:25】开场

**画面**：停在登录页。

**口播**：
> 这是我做的 CampusRun，一个校园跑腿系统。南审的学生可以发单请人代取快递，另一个学生接单赚酬劳。
> 接下来我用两个账号，把完整流程走一遍：注册、发单、抢单、送达、确认收货。

---

### 【0:25–1:00】注册两个账号

**画面**：窗口 A 注册发单人；窗口 B 注册接单人。

**动作**：
1. 窗口 A 点「注册」，昵称填 `小王`，手机号 `13800000001`，密码 `test1234`，提交
2. 窗口 B 同样注册，昵称 `小李`，手机号 `13800000002`，同样的密码

**口播**：
> 先注册两个账号：小王是发单人，小李是接单人。手机号是登录凭证，密码用 bcrypt 哈希存储，数据库里看不到明文。

> 💡 **加分动作**（可选）：如果你想让老师信服，这里可以切到终端敲一句
> `docker exec cr-pg psql -U campusrun -d campusrun -c "select phone_enc, password_hash from users limit 2;"`
> 让镜头看到密文。**这一下比说十句都有用。**

---

### 【1:00–1:45】发单

**画面**：窗口 A（小王）点右下角「+ 发单」。

**动作**：
1. 类型选「快递代取」
2. 起点选「菜鸟驿站」，终点选「梅苑1号楼」
3. 酬劳点 `+` 到 `6.0`（演示 0.5 步进）
4. 期望时长选「30 分钟」
5. 描述填「麻烦帮取一下，取件码 8-2-5031」
6. **取件码填 `8-2-5031`**
7. 提交

**口播**：
> 发单要选起终点——不能手填坐标，必须从学校的地点字典里选，这样推送时才能算距离。
> 酬劳只能 0.5 元一档。选了「快递代取」就必须填取件码，因为这是代取场景的核心信息。

**强调点**（提交后停 2 秒）：
> 取件码落库前会被加密，数据库里存的不是这串数字。

---

### 【1:45–2:30】切账号抢单

**画面**：窗口 B（小李），刷新大厅。

**动作**：
1. 刷新，看到刚发的单（起点→终点、酬劳、倒计时）
2. 点「抢单」

**口播**：
> 小李在大厅里看到了这一单，倒计时还在走——这是发单时设的 30 分钟。
> 他点抢单。

**抢单成功后停在详情页**：
> 现在订单进了「进行中」，时间轴上「接单」这一节点亮了。
> 注意底部的按钮变成了「已取件」——**这个按钮只有接单人才看得到**。

---

### 【2:30–3:15】履约三步

**画面**：窗口 B 顺序点三个按钮。

**动作**：`已取件` → `配送中` → `已送达`

**口播**：
> 接单人按顺序上报：已取件、配送中、已送达。
> 这三个节点不能跳级——我试过直接点「已送达」，系统会拒绝。因为「已取件」是接单人自证的关键证据，跳过它，一旦出纠纷就说不清东西到底在谁手上。

**送达后**：
> 现在是「待确认」，等发单人确认收货。

---

### 【3:15–4:00】切回发单人确认

**画面**：窗口 A（小王），进「我的订单」→ 该单 → 点「确认收货」。

**口播**：
> 切回小王的账号。他看到订单已经送达，点确认收货。
> 这个按钮只有发单人能点——接单人点会报「无权操作」。

**确认后**：
> 订单变成「已完成」，六个节点全部打勾。整条链路走完了。

---

### 【4:00–4:40】收尾：证明数据是真的（**别跳过这一段**）

**画面**：切到终端，敲一条 SQL。

```bash
docker exec cr-pg psql -U campusrun -d campusrun -c \
  "select id, status, runner_id, order_no from orders order by id desc limit 3;"
docker exec cr-pg psql -U campusrun -d campusrun -c \
  "select action, seq, actor_role from order_progress where order_id=1 order by seq;"
```

**口播**：
> 最后我想证明一下这不是前端演的。这是数据库里的真实数据：订单状态是已完成，接单人是小李的 id。
> 下面是这张订单的完整事件流，六条记录，从发单到确认收货，一条不少。
> 这套系统有一个设计原则：**状态不是一个字段，而是一串不可篡改的事件**。订单的当前状态，是把这串事件重放出来的结果。

---

### 【4:40–5:00】结束

**口播**：
> 这就是完整的一条业务链路。谢谢。

## 二、如果出问题（兜底话术，不要慌）

| 现象 | 原因 | 当场怎么说 |
|---|---|---|
| 大厅是空的 | 没刷新 / POI 种子没导 | 「我刷新一下」→ 点刷新按钮 |
| 发单报「不在可发单时间」 | 当前不在 07:00–23:00 | **不要在录屏时遇到**，提前改时间或改配置 |
| 抢单报 403 | 抢了自己的单 | 「这个号是发单人，我换成接单人」 |
| 页面白屏 | 后端没起 | 切终端重启，**这段剪掉重录** |
| 确认收货报 403 | 当前是接单人账号 | 切回发单人 |

**原则**：任何一步错了，**不要解释技术细节**，直接说「我重来一下」，然后继续。剪辑时剪掉。

## 三、录屏参数建议

- 分辨率：1920×1080（网页缩放调到 110%，字大一些）
- 录屏工具：OBS 或 Windows 自带 `Win+G`
- **开麦克风前先试录 10 秒**，确认没有电流声
- 鼠标移动放慢，点击前停顿半秒——观众要看清你点了哪

## 四、和口播视频的分工

| 视频 | 内容 | 时长 |
|---|---|---|
| **演示视频**（本脚本） | 系统能跑什么 | 3–5 分钟 |
| **口播视频** | 我怎么做的、踩了什么坑、学到什么 | 3–5 分钟 |

两个视频**不要讲同一件事**。演示视频证明「东西能用」，口播视频证明「你想明白了」。
